timetap

A personal time-logging web app. Google Apps Script, four files, no dependencies.

Automate capture. Never automate judgment.

Logging costs one tap. The app never interprets, scores, advises, summarises, reminds or nudges. Every conclusion is drawn by the human, later, elsewhere.

You maintain a PLAN calendar by hand — intent, written Sunday. The app writes an ACTUAL calendar — record, written continuously — plus a SITTING calendar as a posture overlay. Comparing them is a weekly manual ritual the app does not participate in beyond emitting raw numbers.

Files

  • appsscript.jsonManifest. One OAuth scope. Set your timezone here.
  • Code.gsServer. CONFIG block, calendar reads and writes, week aggregation.
  • Index.htmlClient. All HTML, CSS and JS inlined. No CDN, no build step.
  • SETUP.mdDeployment steps and the required Google Calendar settings.

The open-block mechanism

The calendar is the source of truth, not localStorage. Tapping a category immediately creates an event with start = now, end = now + 1 minute, and #open in the description. The next tap patches the end to that instant, applies the mark, and strips #open.

This survives a dead battery and a reinstall. On load the open block is found by querying the calendar, not by trusting the browser. The UI updates on tap; the write happens in the background, and a failed write is queued in localStorage — ordered and idempotent — then retried on the next interaction and on load.

The mark

The mark belongs to the block that just closed, captured at the transition — the one moment you both know how it went and are already holding the phone. Never asked for on a block that is starting.

A closed block shows the + = - strip only if its category has no autoMark and it ran at least MIN_MARK_MINUTES. Ignoring the strip costs zero taps: it dismisses itself and = stands. You should see it two to four times a day. If you see it constantly, the design has failed.

Sitting

Sitting is an overlay, not a seventh category. Categories are a partition — exactly one true at a time. You sit while doing deep work, meetings, meals. Only sitting is logged; standing is never written, and non-sitting time is computed at review as waking span minus sitting.

The only coupling in the entire app: tapping BODY closes an open SIT block. That is definitional, not inference. No accelerometer, no screen time, no heuristics, ever.

Monospace, selectable, copyable. No charts. No colours. No highlighting of problem rows. No commentary. No totals versus last week. The numbers, and nothing else.

Non-goals

  • Notifications, reminders, alerts, nudges, sit-time warnings
  • Any automatic detection: screen time, location, motion, calendar inference
  • Streaks, scores, badges, gamification, encouragement
  • AI summaries, insights, recommendations, generated review text
  • Charts, graphs, sparklines, progress bars
  • Accounts, auth, databases, external services, analytics
  • A settings screen — configuration is the CONFIG block in Code.gs
  • Writing to the PLAN calendar in any way

This page is documentation. The app itself does not run here — it runs as a Google Apps Script web app deployed under your own account, with access set to only yourself. See SETUP.md.
